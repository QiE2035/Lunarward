# 19 · 测试方案（最终版）

> 目标：**把「感觉还有好多 bug」变成一份可执行的证据链**。本文件是唯一测试计划：每条用例有 ID、层级、期望、证据形式与判定阈值；性能与稳定性有量化预算；缺陷必须能回指用例，修完的提交必须带用例 ID。
>
> 维护规则：新增模块必须先在本表登记用例；删除用例要写理由；预算表中的阈值改动要有一次实测数据支撑（记在 §9 基线表里）。

- 最后更新：2026-11-12
- 对应代码：`src/Lunarward`（`main`），单头 Linux，不改 `src/Starward/`
- 现状：L1 单测 36 条；L2/L3/L1.5 尚未搭建（本轮要落地的是 M-T1～M-T4）

## 1. 质量目标（可判定的那种）

| 维度 | 目标 | 判定方式 |
|---|---|---|

## 2. 分层

| 层 | 名字 | 跑在哪 | 依赖 | 频率 | 判定 |
|---|---|---|---|---|---|
| L1 | 单元测试（xunit） | CI | 无 GUI / 无 wine | 每次 push | 全绿才可合并 |
| L1.5 | 进程内 UI 断言（`--selftest-ui`） | CI（`xvfb-run`）/本机 | 只需 X11 | 每次 push | 全绿才可合并 |
| L2 | CLI / 无头集成 | CI | 临时 XDG + 假前缀 + 假 Sophon | push 冒烟 + 每晚全量 | 全绿才可合并 |
| L3 | GUI 端到端（真实输入） | 本机 X11 | 真实会话 + wine + `cu_*` | 每轮手跑 + 每晚关键集 | 关键集必须过 |
| L4 | 人工验收 | 本机 + 真实账号 | 用户在场 | 里程碑 | 清单逐项勾选 |
| LP | 性能 / 稳定性（可跨层） | CI + 本机 | 采样脚本 | 每晚 + 里程碑 | §6 预算 |

**隔离**：L1.5/L2/L3 一律把 `XDG_CONFIG_HOME`、`XDG_DATA_HOME`、`XDG_CACHE_HOME`、`XDG_STATE_HOME` 指向 `mktemp -d`；测试前缀只建在 `$TEST_DATA/prefix`；安装类用例只在 `$TEST_DATA/games` 下建 `lw-test-*`。

### 2.1 关于 `Uno.UITest`：不采用（有证据）

- 官方 *Using Uno.UITest* 明确写「not yet supported: **SkiaSharp backends (GTK, WPF, Tizen)**, Xamarin.macOS, Windows」；只支持 WebAssembly（Selenium）与 iOS/Android（Xamarin.UITest/AppCenter）。
- NuGet 上 `Uno.UITest`、`.Helpers`、`.Xamarin`、`.Selenium` 全部停在 `1.0.0`，没有 X11/Skia driver。
- 我们目标框架 `net10.0-desktop` 正好落在不支持区间；编成 WASM 也测不到 wine/GTK/X11 的真实链路。
- 替代：L1.5（进程内断言）+ L3（真实输入）。

## 4. 测试夹具（fixtures）

1. **假前缀**：最小目录结构（`drive_c`、`system.reg`、`user.reg`、`.lunarward/prefix.json`），几十 KB，用于不需要 wine 的用例。
2. **假 Sophon**：本地 `HttpListener` 提供 `getBuild`/`getPatchBuild`/chunk 下载，可切 4xx/5xx/429/超时/短读；清单用 3 个小文件 + 1 个补丁，秒级跑完。
3. **假运行器**：可执行 shell 脚本扮演 `wine`/`wine64`/`wineserver`（打印版本、把参数写日志），用于验证 env 与「首进程」约束。
4. **假媒体**：8 秒 webm（VP9）、损坏 webm、超大 webp（2560×1440）、仅透明层 webp（复现主题图叠层）。
5. **假外部命令**：PATH 里放假的 `spectacle`/`grim`/`xdg-open`/`notify-send`/`fuser`，用于断言调用参数（并覆盖「缺失」分支）。
6. **回归样本**：每个已修 bug 一份最小复现数据（坏 JSON、尾斜杠前缀路径、公告空卡片场景等）。

## 6. 性能预算与判定

| 指标 | 预算 | 采样方法 |
|---|---|---|
| 冷启动 | ≤ 3.0 s（`Process.Start` → 首帧日志） | 应用内打点 + 日志时间戳 |
| 空闲 CPU | ≤ 5% | `/proc/<pid>/stat` 10 s 差分 |
| 视频背景 CPU | ≤ 1.2 核 @30fps | 同上 + 线程分解（`df0` 等） |
| 页面切换 | 首 ≤ 400 ms / 再 ≤ 100 ms | `[nav-diag]` 命名字段 |
| 内存 | 空闲 ≤ 600 MB；切页/图库增量 ≤ 150 MB | `/proc/<pid>/status` VmRSS + GC 计数 |
| fd / 线程 | 增长为 0（±2） | `/proc/<pid>/fd` 计数、`/proc/<pid>/status` Threads |
| 安装吞吐 | ≥ 10 MB/s（8 并发） | 下载器日志统计 |
| UI 帧 | 切页/滚动不掉到 < 20 fps | 帧计数日志（30fps 基准） |

判定：连续 3 次采样取中位数；与 §9 基线偏差 > 20% 视为回归（需在 PR 里说明原因或修）。

## 7. 方法与工具

- **L1**：`dotnet test`（xunit）。新增纯逻辑必须先加断言（路径、解析、状态机、序列化）。
- **L1.5**：应用内 `--selftest-ui`，用例清单驱动，`PASS/FAIL` + 退出码；`xvfb-run` 可跑。
- **L2**：`scripts/test/cli-smoke.sh`（39 命令错误路径）、`scripts/test/sophon-fake.sh`（本地假服务）、`scripts/test/fixtures.sh`（造假前缀/假运行器）。
- **L3**：`cu_*`（真实输入 + 截图）+ 日志断言 + 像素判据（区域均值/标准差/自相关节距）；每个用例一个脚本 `scripts/test/gui/T-XX-YY.sh`，输出证据路径。
- **LP**：`scripts/test/perf.sh`：起应用 → 跑场景 → 采样 `/proc` → 生成 `perf-<sha>.json` → 与 `scripts/test/perf-baseline.json` 比对，超阈值退出码非 0。
- **故障注入**：`scripts/test/faults/*.sh`（kill -9 时点、磁盘满用小 tmpfs、权限、断网用 `unshare -n` 或本地代理）。
- **证据规范**：失败用例必须留下（a）命令与方法版本（b）日志片段（c）截图（d）`--diagnose` 包路径。

## 8. 缺陷流程与门禁

- **Issue 模板**：环境（诊断包）、步骤、期望/实际、证据、严重度（S1 起不来/丢数据；S2 功能不可用；S3 观感；S4 建议）。
- **规则**：S1/S2 必须先补用例（L1/L2 优先，GUI 则 L3 脚本）再修；修完提交信息带用例 ID（例：`fix(runtime): 前缀尾斜杠 (T-LA-03)`）。
- **门禁**：push → L1 + L1.5 + L2 冒烟；每晚 → L2 全量 + L3 关键集 + LP 预算；发布前 → P0 全绿、S1/S2 清零、LP 无回归。
- **防伪绿**：不允许为了让用例过而放宽断言；不允许 mock 掉被怀疑的那一层（要么修代码，要么改用例并在 PR 说明）。
