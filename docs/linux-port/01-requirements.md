## 二、需求清单

### R-01 界面与交互保真（P1）

**描述**：Linux 版的页面结构、控件、导航、文案、动效节奏与 Starward 一致；关键页面达到「同一套设计语言」的可辨识度。

**验收判据**：
1. 游戏启动页、设置页、战绩页、抽卡页、截图页与上游同页结构逐项对照无缺项；
2. 导航层级与入口位置一致；
3. 中文文案与上游一致（允许术语增补）；
4. 深色主题、圆角、阴影、层级关系与上游视觉语言一致（模糊/装饰类允许差异）。

**关联**：D0、D18、R-13

### R-02 统一组件库（P2）

**描述**：wine / proton / dxvk / vkd3d-proton / dxvk-nvapi / 前缀模板统一登记、统一版本显示、可被多个运行环境引用，**同一版本只存一份**。

**验收判据**：
1. 同一 wine 目录被 3 个运行环境引用时，磁盘上只有一份；
2. 组件有来源、版本、指纹（校验和或版本串）三项可查信息；
3. 删除被引用的组件时给出阻断提示与引用清单。

**关联**：D5、D6、D9

### R-03 可组合运行环境（P2）

**描述**：运行环境（Profile）可灵活组合运行器、前缀策略、图形组件版本、环境变量、命令/参数、包装器、钩子、伴随项，并可被多个游戏复用。

**验收判据**：
1. 同一运行环境被 4 个游戏引用，改动一处全部生效；
2. 运行环境可导出为单个文件、可导入还原（含组件版本约束）；
3. 游戏级覆盖与运行环境默认值可同时查看，来源标注清晰。

**关联**：D4、`03-runtime-model.md`

### R-04 前缀可选隔离（P2）

**描述**：同一游戏可选用共享/独立/克隆/外部前缀；不同组合之间互不干扰；克隆成本可接受。

**验收判据**：
1. 在 btrfs/XFS 上克隆一个初始化完成的前缀 < 2 秒（reflink）；
2. 两个克隆体并发启动时，后启动者被明确阻断并提示占用者；
3. 支持直接引用 anime-game-launcher / sleepy-launcher / Lutris / Bottles 的既有前缀。

**关联**：D5、D6

### R-05 外部组件复用（P2）

**描述**：可直接引用系统、Steam（含 `compatibilitytools.d`）、umu、Lutris、Bottles、Heroic、自定义路径中的 wine/proton/dxvk，且不复制。

**验收判据**：
1. 扫描结果列出「来源 / 类型 / 版本 / 路径」；
2. 引用外部组件后，该组件不进入本项目数据目录（除非用户显式「接管/导入」）；
3. 外部组件消失时，运行环境标记为「不可用」并给出原因，而不是启动失败在游戏层。

**关联**：D9

### R-06 直接启动与「首个 wine 进程」约束（P3）

**描述**：游戏必须以直线 `exec` 链启动，不引入常驻父进程；监控与伴随项由外部代理负责。

**验收判据**：
1. 启动链上任一环节均为 `exec`，进程树中游戏进程的父进程为 `wine`/`wine64`（或 gamescope 等 wine 之外的进程）；
2. 提供「启动计划预览」，展示最终 argv、env、cwd、prefix；
3. 提供启动前检查：同 prefix 残留 wineserver / 其他 wine 进程会阻断启动。

**关联**：D7、`02-architecture.md` 进程模型

### R-07 后启动 / 伴随启动（P3)

**描述**：可配置在游戏启动后、按条件触发的辅助工具；支持「伴随启动」开关把常用条目升级为自动执行。

**验收判据**：
1. 支持 5 种触发条件（见 D7）并可组合；
2. 独立进程型与注入型工具均可配置；
3. 每个伴随项有超时、失败策略（忽略/提示/中止后续）、日志；
4. 伴随项失败不影响游戏本体运行。

**关联**：D7

### R-08 启动报告（P3 派生）

**描述**：每次启动产出结构化报告（计划、组件指纹、时间线、退出归因），用于排障与组合对比。

**验收判据**：
1. 报告含 plan 快照、各阶段耗时、退出码、崩溃归因分类；
2. 报告可在 UI 中查看并一键复制路径/内容；
3. 报告不包含账号凭据类敏感信息（脱敏规则见 `03-runtime-model.md`）。

**关联**：D7、`03`

### R-09 调试终端（P4）

**描述**：为运行环境提供快速打开 shell 的能力，环境与真实启动完全一致。

**验收判据**：
1. `env` 输出与启动计划 env 逐项一致（允许 shell 自身注入项，需标注）；
2. 支持 bash/zsh/fish/自定义；
3. 提供单次命令执行、打开前缀 C 盘、winecfg/regedit/winefile 快捷入口；
4. 终端不可用时（无 emulator）给出明确提示与可复制命令。

**关联**：D8

### R-10 需求池开放（P5）

**描述**：允许持续追加痛点与需求，按同一流程落库。

**验收判据**：新需求进入 `08-open-questions.md` 后有编号、有来源、有建议方案。

### R-11 文档先行与变更留痕（要求1）

**验收判据**：
1. 所有已定事项在 `00-decisions.md` 有唯一编号；
2. 未决事项在 `08-open-questions.md` 有编号；
3. 任何源码改动都能追溯到某条已确认决策 + 用户明确的开工指令。

### R-12 第三方依赖优先（要求2）

**验收判据**：
1. 每个新模块在实现前，`05-dependencies.md` 中记录「是否已有现成依赖」；
2. 引入依赖需满足准入标准（见 `05` 第一节）；
3. 禁止自研已有成熟实现的基础能力（解压、下载、D-Bus、PE 解析等）。

### R-13 移植保真（要求3）

**验收判据**：
1. `Starward.Core`、`Starward.Language` 代码保持原样（仅允许路径/UA 等最小适配）；
2. 82 个 XAML 中，除平台子系统外不得重写页面结构；
3. 任何「看起来像重写」的改动必须先立 ADR 说明理由。

### R-14 主动提出更优方案（要求4）

**验收判据**：每轮设计产出至少包含一次「替代方案对比」，并在 ADR 中保留未采纳的备选。

### R-15 Linux 必须可用（m00115）

**验收判据**：
1. 在 CachyOS（Arch 系）+ KDE/Hyprland 会话下可完整使用；
2. 不依赖任何 Windows 运行时（WinAppSDK/WebView2 Runtime/MSIX）；
3. `07-roadmap.md` M0 门禁全部通过。

### R-16 真机验收游戏（m00119）

**验收判据**：

| 游戏 | 路径 | 判据 |
|---|---|---|
| 原神（国服） | `~/games/hk4e_cn` | 启动进入游戏主界面、可登录、可正常退出；游玩 ≥ 10 分钟不崩溃 |
| 绝区零（国服） | `~/games/nap_cn` | 同上，且 ACE 反作弊不报错 |


### R-17 两个 CRUD 列表（m00662 / m00676）

| 列表 | 作用域 | 必备能力 | 验收判据 |
|---|---|---|---|
| Profile 列表 | **全局**（设置 → 运行环境） | 增删改查、复制、`打开调试 shell`、查看启动日志 | 建一个 Profile 后能被任意游戏引用；复制出的 Profile 改组件后互不影响 |
| 后启动程序列表 | **按游戏**（游戏设置页分区） | 增删改查、复制、拖拽排序、`伴随`开关、`▶ 手动启动`、从其他游戏导入 | 同一游戏可配多条；伴随条目在游戏启动后按顺序串行执行，间隔可配 |

字段定义见 `09-profile-and-companion-ui.md` §2/§3；锁冲突与串行策略见 §4。

### R-18 输出可见性（m00676 / m00679）

**判据**：①游戏本体、后启动条目、启动器本体三处的输出都能看，且「捕获永远开启、级别只控制显示」；②`Ctrl+Shift+L` 可在 1 秒内调出实时日志面板；③从终端启动时启动器正常打印，从桌面（KDE）启动时不产生任何终端噪音、日志照常落盘；④关闭终端不会终止正在运行的游戏。

模型见 `00-decisions.md` D27，实现约定见 `09-profile-and-companion-ui.md` §5–§7。

| 编号 | 非目标 | 理由 |
