# 17 · 运行环境：逻辑与 UI 最终方案（v2）

> 状态：**最终设计稿，代码未改动**。配套：D58（运行组件 v2 极简）、D61（删模板库）、D62（跨页刷新）、D63（本条决定）。
> 用户已确认的四条方向（2026-11-12）：方案编辑改**独立页**；前缀**单独成段**；运行器**只读 + 手动添加路径**；游戏页保持下拉、只加「诊断」。

---

## 0. 一句话

启动器只管三件事：**看得见有哪些运行器、每个游戏用的是哪套、出问题时怎么换回来**；DXVK/VKD3D 是"装进前缀的产物"，因此它的管理挂在**前缀**上，而不是单独一个市场页。

## 1. 概念与边界

| 实体 | 是什么 | 谁管 |
| --- | --- | --- |
| 运行器（runner） | 能被 `wine` 命令直接驱动的目录（`bin/wine` 或 `files/bin/wine`，且能解析到同套 `wineserver`） | **只读**：扫描 + 手动添加路径；不复制、不下载、不删除 |
| 方案（profile） | 一套配置：运行器 + 图形层选择 + 前缀来源 + 环境变量 + 调试 Shell + 输出级别 | 由本应用创建/编辑/删除 |
| 前缀（prefix） | wine 的 C 盘；会坏、会占几十 G、会被多个方案共用 | 我们创建的（新建/复制/临时）可清理；`external` 只读 |
| 图形层（DXVK/VKD3D） | 组件本身（目录）；装进前缀后成为前缀的一部分 | 组件只读发现（可删除我们自己导入的）；**前缀里的安装/移除/校验归前缀** |
| 游戏绑定 | 游戏 → 方案 | 由本应用维护（`ProfileBinding`） |

## 2. 数据与判定

- 运行器：`path`、`version`、`layout`（`bin`/`files-bin`）、`usable` + `reason`、`usedByProfiles`（现算）、`manual`（是否手动添加）。
  原因沿用现有四条：找不到可执行文件 / 没有执行权限 / `wine --version` 无输出 / 找不到配套 wineserver。
- 方案：`name`、`runnerPath`、`graphicsId`（DXVK）、`vkd3dId`（可选）、`prefixMode`（新建 `/` 复制自现有 `/` 使用已有 `/` 临时）、`prefixPath`、`env`、`shell`、`output`、`boundGames`（现算）、`lastLaunch`（来自 `LastKnownGoodStore` + 最近 `logs/launch/*.json`）。
- 前缀：`path`、`origin`（我们的 / 外部）、`sizeBytes`（进页算一次，缓存 10 分钟）、`usedByProfiles`、`state`：
  `健康` / `缺少 drive_c` / `正被占用` / `不存在`。
- 前缀里的图形层：读 `<prefix>/.lunarward/graphics.json`（id、name、kind、source、installedAt、files），与**实际文件**比对（存在 + 大小；SHA 为可选开关）→ `与记录一致` / `不一致（N 个缺失）` / `未安装`。
- 组件去重：DXVK 按 `x64/d3d11.dll`、VKD3D 按 `x64/d3d12.dll` 的 SHA-256 分组；同组折叠一行，展开列来源并标注 `系统包` / `其它启动器` / `本应用导入`。哈希结果并入 `ComponentStore` 缓存，随「刷新」失效。

## 3. 页面 A：设置 → 运行环境（三段）

```

 系统 Wine         9.0   不可用：找不到配套 wineserver  [复制路径]

方案                                     [新建方案]
 默认（opt）  spritz-wine-tkg  DXVK 3.1.1  专用前缀
 绑定：原神·星穹铁道   上次启动 10:31 成功        [编辑] [诊断]
 试验用       系统 Wine       无图形层     使用 ~/.wine
 绑定：无              上次启动 昨天 失败（预检 2 项） [编辑] [诊断]

前缀
 专用·原神        12.4 GB  2 个方案  健康
 已装 DXVK 3.1.1 · 与记录一致                  [打开] [重装] [移除] [清理]
 使用已有·系统     3.1 GB   1 个方案  缺少 drive_c
 未安装图形层                                  [打开]
```

要点：
- 空态：无方案时显示「还没有方案，[新建方案]」+ 一句说明；无运行器时提示「没有找到 wine，可手动添加路径」。
- 「添加路径…」：选一个 `wine`，跑一次 `wine --version` 探测，成功则写入 `~/.config/lunarward/manual-runners.json`（原子写），与扫描结果合并并标「手动」。
- 前缀「清理」只对**我们创建的**前缀出现，且要求 `usedByProfiles == 0` 且未被占用；二次确认。
- 前缀大小：进页算一次并缓存 10 分钟，行上显示计算时间（悬停）。

```
  [ ~/.local/share/lunarward/prefix/hk4e-1        ] [浏览…]

```

- 保存前轻校验：运行器存在且可用、前缀可解析（不存在且选了「使用已有」则报错），不弹二次确认。
- 新建方案默认：运行器 = 列表第一个可用项；图形层 = 上次用过的；前缀 = 新建，路径 `prefix/<biz>-<id 前 8 位>`。
- 删除方案**不**连带删前缀，提示「还有 N 个方案/游戏在用」。

## 5. 图形层（DXVK / VKD3D）细则

1. **分组**：按 SHA-256 把同内容组件折叠成一行（本机实测 `/usr/share/dxvk` 与两个其它启动器目录里有 3 份相同的 3.1.1）。
2. **组件动作**：`安装到前缀…`（选前缀后装）、`打开目录`、`删除`（仅 `components/` 下我们自己导入的；系统包与其它启动器目录标灰并注明管理者）。
3. **前缀侧状态**：前缀行第二行显示 `已装 xxx · 与记录一致 / 不一致（N 个缺失）/ 未安装`，操作 `安装/重装`、`移除`、`校验`。
4. **移除**：按 `graphics.json` 的 `Files` 列表删文件，再删记录；外部前缀（`external`）默认不允许移除（避免动别人的 C 盘），仅在用户显式确认后执行。
5. **迁移/回滚**：换版本时先按旧记录移除再装新的（消灭覆盖残渣）；`graphics.json` 每次写入前保留一份 `graphics.json.bak`。
6. **不做**：不下载 DXVK、不检查更新（沿用 D58 v2）、不动 `WINEDLLPATH` 叠加（未验证 wine 能否从该路径加载 native d3d11，标为待验证，不进实施）。

## 6. 游戏设置页

保持现有方案下拉；右侧加 `[诊断]`，调用 `LaunchPreflight.Check` 并弹现有可点修复对话框。绑定失效时保留 D61 的 InfoBar。

## 7. 文案与状态表

| 场景 | 文案 |
| --- | --- |
| 运行器可用 | `可用 · bin` / `可用 · files-bin` |
| 运行器不可用 | 四条原因之一（不加"错误"字样，直接说原因） |
| 方案上次启动 | `上次启动 10:31 成功` / `上次启动 昨天 失败（预检 2 项）` / `上次启动 未知` |
| 前缀状态 | `健康` / `缺少 drive_c` / `正被占用` / `不存在` |
| 图形层 | `已装 DXVK 3.1.1 · 与记录一致` / `不一致（3 个缺失）` / `未安装` |
| 空态 | `还没有方案，[新建方案]` / `没有找到 wine，可手动添加路径` |

## 8. 分期与验收

- **P1**（先让信息可见）：三段页面骨架 + 运行器分组与 `usedByProfiles` + 前缀段（状态/大小/共用）+ `PrefixManager.Inspect`。验收：真机截图三段齐全，前缀大小与实际 `du` 一致，占用前缀能标出。
- **P2**：方案独立编辑页 + 游戏页「诊断」。验收：新建/编辑/前缀四选都通；保存前校验能拦住不可用运行器。
- **P3**：图形层分组去重 + 前缀侧安装/移除/校验 + `graphics.json.bak`。验收：把前缀里 `d3d11.dll` 删掉后状态变「不一致」，重装恢复「一致」。
- **P4**：手动添加运行器、前缀「清理」、`lastLaunch` 徽标。

## 9. 不做

- 组件下载 / 多 provider 市场 / 锁文件 / 漂移检测（D58 v2 收回）；
- 复制或删除系统组件（2026-11-11 用户边界）；
- 前缀模板库（D61 已删）；
- `WINEDLLPATH` 叠加（待验证，不进实施）。

## 10. 待定（我给默认，可改）

1. 前缀大小缓存 10 分钟（改大省 IO、改小更准）。
2. 运行器列表默认全展开，超过 8 个才折叠。
3. `external` 前缀的图形层允许「移除」需二次确认（默认为不允许）。
4. 组件 SHA 分组默认开启；目录很多时可关（设置里不暴露，走环境变量 `LUNARWARD_NO_COMPONENT_HASH=1`）。
