## 4. 工作流程（强制）

1. **先讨论，后落文档**：新需求先在对话里确认；动代码前把结论写成 `00-decisions.md` 的新条目（D 编号）。
2. **决策不覆盖，只追加**：改结论时新增变更记录行，保留旧结论与改判原因。
3. **文档先行于代码**：实现前，行为必须已在 `00` 或 `23` 里有可验收描述。
4. **未明确即不做**：未授权的细节不得「顺手实现」；**批准范围不得扩大**（D46 第 6 条）。
5. **结论必须有论据**：能复现、区分实测与推断、可视化问题要量化、猜错要撤回并留档（D46）。
6. **文档与代码同源**：行为变化的提交必须同步文档（`00` 追加决策 / `13` 记坑 / `CHANGELOG.md` 记版本）。
7. **偏差要标记**：偏离上游的地方在源码里写 `// LUNARWARD-DEVIATION: 原因`，并在 `12` 登记。

## 5. 术语表（中英对照）

| 中文 | 英文 | 含义 |
| --- | --- | --- |
| 组件 | Component | 可寻址的版本化产物：wine / proton / dxvk / vkd3d-proton / dxvk-nvapi |
| 运行器 | Runner | 真正执行游戏的运行时：系统 wine、Steam 的 `files/bin/wine`、手动添加路径。只有装在 `/usr`、`/bin`、`/sbin` 的才叫「系统 Wine」，其余用目录名；重名时追加来源（D87） |
| 前缀 | Prefix | Wine prefix（`drive_c` + 注册表）。**本项目的「前缀」只是方案里的一个路径字段**（D74）：留空 = 用默认目录并在首次启动时创建，不再有 `dedicated/template/external` 这类型别 |
| 方案 | Profile | 可命名的启动配方（schema 4）：运行器 + DXVK + VKD3D-Proton + 前缀 + env / 参数 / 包装 + 增强（HUD / gamemode / gamescope） |
| 图形层 | Graphics layer | 装进前缀的 DXVK / VKD3D-PROTON 一组 DLL |
| 后启动程序 | Companion | 游戏启动后（或退出后）按条件触发的辅助工具 |
| 一次性运行 | Run once | 在与目标游戏相同的环境里跑一次任意程序（`RunOnceService`、`--run-once`） |
| 调试 Shell | Debug shell | 在同一环境下打开交互式终端 |
| 启动报告 | Launch report | `logs/launch/<时间>-<biz>.json`，含预检逐项结果 |
| 上次可用 | Last known good | `~/.config/lunarward/last-good.json`，用于一键回退 |
