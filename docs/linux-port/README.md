## 工作流程（必须遵守）

1. **先讨论，后落文档**：任何新细节先进入 `08-open-questions.md`（带编号），不改 `00-decisions.md`。
2. **用户确认后才升级**：用户明确答复后，在 `00-decisions.md` 记录结论与理由，并在 `08` 中把该条标记为「已归档 → Dxx」。
3. **文档先行于代码**：任何功能实现前，其行为必须已在 `01`/`03` 中有可验收的描述。
4. **未明确即不做**：文档未覆盖的细节一律视为未授权，不得「顺手实现」。
5. **决策不覆盖，只追加**：变更决策时新增变更记录行，保留旧结论与变更原因。
6. **文档与代码同源**：涉及行为变化的改动，必须同步更新对应文档，否则视为未完成。

## 术语表（中英对照）

| 中文 | 英文 | 含义 |
|---|---|---|
| 组件 | Component | 可寻址的版本化产物：wine / proton / dxvk / vkd3d-proton / dxvk-nvapi / 前缀模板 |
| 运行器 | Runner | 真正执行游戏的运行时：wine、proton、umu、自定义脚本 |
| 前缀 | Prefix | Wine prefix（win64/win32 的 C: 盘与注册表） |
| 运行环境 | Profile | 可命名、可复用、可导出的启动配方（运行器 + 前缀策略 + 组件版本 + env + 包装器 + 钩子 + 伴随项） |
| 游戏条目 | GameEntry | 一个游戏：安装路径 + 绑定运行环境 + 游戏级覆盖 |
| 启动计划 | LaunchPlan | 一次启动解析出的最终 argv/env/cwd/prefix/伴随项，可预览、可复制、可记录 |
| 启动会话 | LaunchSession | 一次真实启动的实例，产出 `LaunchReport` |
| 伴随启动 | Companion | 游戏启动后按条件触发的辅助工具条目 |
| 监控代理 | Agent | 与 GUI 分离的守护进程，负责观测游戏进程并触发伴随项 |
| 调试终端 | Debug Shell | 在与启动计划完全相同的 env/prefix 下打开的交互式终端 |
| 包装器 | Wrapper | gamescope / gamemoderun / mangohud 等 exec 型外层工具 |
