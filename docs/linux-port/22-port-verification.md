## 3. 缺陷

### P0-1（已更正）窗口按物理像素开，但缩放比例是 1.0 —— 原判断作废
- 更正依据：把窗口从 1200 缩到 900 物理像素后，页面自动变成单列（说明 `SizeChanged` 的宽度单位与物理像素一致，缩放比为 1.0，不存在「DIP 面积缩水」）。
- 因此 1200×680 物理 = 1200×676 DIP，与上游设计尺寸一致；**不需要放大窗口**（用户已明确：现在尺寸合适，放大如「老年机」）。

### P0-2（已修，2026-11-13）游戏设置页「HDR 块与运行配置重叠」
- 复测结论：**不存在横向溢出**。1200 宽（双列）与 1000 宽（单列）下，内容最右文字像素分别在 x=1149 / x=807，均在窗口内 → 原始的「右列越界」判断作废。
- 真实缺陷：滚动到底时「运行配置」标题与 HDR 段落**画在同一位置**（截图 `/tmp/gs_end.png`、`/tmp/gs_end2.png`），并非重绘残留（改窗口尺寸 `/tmp/gs_relayout.png`、最小化恢复 `/tmp/gs_after_min.png` 都不消失）。
- 根因：`GameSettingPage` 内容 Grid 的行高是 `Auto`，而 HDR 分区的 `Visibility` 与 `HDRNotSupported` 在 `InitializeGameSettingAsync` 里异步变成可见 —— Uno 在「先按折叠状态测出行高、后让子项可见」时不重算行高，后出现的块便画到下一行的位置上。
- 修法：`GameSettingPage.xaml` 给内容 Grid 命名 `Grid_Content`；`InitializeGameSettingAsync` 末尾 `DispatcherQueue.TryEnqueue(() => Grid_Content.InvalidateMeasure());`。
- 验证：1200 宽（双列）与 1000 宽（单列）滚动到底均无重叠（`/tmp/fix_a_end.png`、`/tmp/verify_1200_end.png`）。
- 试过但**无效**并已撤回：把底部按钮条的丙烯换成实底（不改变重叠，只改变透出观感）；给 `ScrollViewer_Main` 设 `Clip`（截图与未加时逐像素相同，Uno 未应用）。

### P1-1（已撤回）「窄宽度不降级单列」不成立
- 实测：窗口缩到 900 宽时页面自动单列，断点生效；原判断建立在错误的缩放前提上，作废。

### P1-2（已澄清，非缺陷）底部按钮条与说明文字
- 与 P0-2 同源：修好行高重算后，视口底部只会出现「被裁剪的半行」（滚动视口边缘的正常表现），按钮条本身位置正确。
- 像素复核：`/tmp/final_1200.png` 与 `/tmp/fix_a_1200.png` 的按钮条区域逐像素相同，未出现整行文字压在按钮条上。
