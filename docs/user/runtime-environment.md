# 运行环境怎么配

这一页只回答三件事：游戏用哪个 wine、用哪个图形层、环境放在哪。

## 1. 先看「设置 → 运行环境」

打开后能看到两类东西：

- **运行器**：本机已经能找到的 wine / Proton。每行右边会写「可用 · bin」或不可用的原因。
  不可用最常见的原因是**缺少配套的 wineserver**——那样游玩时长会记错、前缀锁也会失效。
- **方案（Profile）**：一个方案 = 运行器 + 图形层 + 前缀 + 参数。游戏在「游戏设置 → 运行」里绑定方案。

第一次用只需要：新建一个方案 → 选一个标着「可用」的运行器 → 回游戏页点开始。

## 2. 图形层（DXVK / VKD3D）

- 默认建议选一个 DXVK，装进前缀（这是 DXVK 官方推荐方式，兼容性最好）。
- 图形层缺失时游戏会用自己带的 d3d 实现，通常能进游戏但帧率差很多。
- 想「不修改前缀地试一下」可以用叠加模式（`WINEDLLPATH`），个别游戏可能不生效。

## 3. 前缀放在哪

- 默认在 `~/.local/share/lunarward/prefix/<游戏>`，第一次启动时创建（约十几秒）。
- 已经有现成前缀（比如 sleepy-launcher / anime-game-launcher 建的）就选「使用已有目录」——
  启动器**不会复制、不会修改、不会删除**它。
- 想试新 wine / 新 DXVK：克隆一份再试，别动正式的那份。

## 4. 起不来时

游戏页会先做一次预检，逐项说明哪一项不通过，并给出可点按钮：

| 提示 | 点一下 |
|---|---|
| 找不到运行器 | 打开运行环境 |
| 前缀不能写 / 不像前缀 | 打开前缀目录看看 |
| 前缀被占用 | 查看占用进程 |
| 没装图形组件 | 安装图形组件 |

还不行就导出诊断包：

```bash
lunarward --diagnose --out ~/Downloads
```

会生成一个 zip（环境变量已打码、不含存档与账号），报问题时附带它即可。

## 5. 常见现象

- **启动后几秒就退出、日志里出现 `launching from steam.exe stub!`**：前缀路径带了尾斜杠或多了一层目录。检查「运行环境」里的前缀路径。
- **游玩时长明显不对**：运行器缺少配套 `wineserver`，或游戏不是通过启动器启动的。
- **全局热键不生效**：当前是 Wayland 会话。用系统快捷键绑定 `lunarward --show` 代替。
- **托盘没有图标 / 菜单**：需要支持 StatusNotifierItem 的桌面（KDE/GNOME 扩展均可）。
