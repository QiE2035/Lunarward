# 运行环境怎么配

这一页回答三件事：游戏用哪个 wine、用哪个图形层、环境（前缀）放在哪。

## 1. 打开「运行环境」

在左侧栏**最下面、齿轮（启动器设置）正上方**的那个图标。也可以直接 `lunarward --page runtimeenv`。

打开后顶部是一排状态（几个方案、绑定了几个游戏、运行器能不能用、组件数、前缀合计占用），下面四个页签：

| 页签 | 里面有什么 |
| --- | --- |
| **方案** | 左边是方案列表，选一个，右边显示它的运行器 / 图形层 / 前缀 / 增强 / 最近启动；要改就点「编辑方案」 |
| **运行器** | 本机能找到的 wine 和 Proton（含 Steam `compatibilitytools.d` 与自定义库）。每行写「可用 · bin」或不可用的原因 |
| **组件** | DXVK / VKD3D-Proton 的下载、导入、健康检查、清理未使用 |
| **前缀** | 已知前缀、各占多大、哪个方案在用、有没有被占用 |

**第一次用不需要手动配**：还没有对应游戏的方案时，点开始会自动建一个同名方案并绑定它。想改成别的，去「游戏设置 → 运行」换。

## 2. 图形层（DXVK / VKD3D）

- DXVK 管 Direct3D 9/10/11，VKD3D-Proton 管 Direct3D 12，**两个可以同时选**（它们是独立的层）。
- 一般只选 DXVK 就够；只玩 DX12 游戏才需要 VKD3D。
- 图形层没装进前缀时，游戏会用自己带的 d3d 实现，通常能进但帧率差很多。方案详情里如果提示「前缀和方案对不上」，点「同步到前缀」。
- 图形层目前只能**装进前缀**（会替换前缀里的 d3d dll）；想试新的又不想动正式前缀，先克隆一份方案再往里装。

## 3. 前缀放在哪

- **前缀只是方案里的一个路径字段**。留空 = 用默认目录 `~/.local/share/lunarward/prefix/<方案名>`，第一次启动时创建（十几秒）。
- 已经有现成前缀（比如 sleepy-launcher / anime-game-launcher 建的），在「编辑方案」里把路径填进去即可——启动器**不会复制、不会修改、不会删除**它。
- 多个方案共用同一个前缀时，同时启动会抢锁失败，页面会给「为某个游戏克隆一份」。
- 想试新 wine / 新 DXVK：克隆一份方案再试，别动正式那份。

## 4. 起不来时

游戏页会先做一次预检（11 项只读检查：运行身份、可执行文件、运行器、游戏架构、前缀、结构、可写、占用、图形组件、游戏自带 dll、增强开关），逐项说明哪一项不通过，并给出可点按钮：

| 提示 | 点一下 |
| --- | --- |
| 找不到运行器 / 运行器不可用 | 打开运行环境 |
| 前缀不能写 / 不像前缀 | 打开前缀目录看看 |
| 前缀被占用 | 查看占用进程 |
| 没装图形组件 | 安装图形组件 |
| 游戏目录里有自带 d3d dll | 打开游戏目录，把多余的改名（加 `.bak`） |
| 游戏架构和前缀对不上 | 打开运行环境改前缀架构 |

还不行就导出诊断包：

```bash
lunarward --diagnose --out ~/Downloads
```

会生成一个 zip（环境变量已打码、不含存档与账号），报问题时附带它即可。

## 5. 常见现象

- **启动后几秒就退出、日志里出现 `launching from steam.exe stub!`**：前缀路径带了尾斜杠或多了一层目录。检查「运行环境 → 方案 → 前缀」里的路径。
- **游玩时长明显不对**：运行器缺少配套的 `wineserver`，或游戏不是通过启动器启动的。
- **全局热键不生效**：当前是 Wayland 会话。用系统快捷键绑定 `lunarward --show` 代替。
- **托盘没有图标 / 菜单**：需要支持 StatusNotifierItem 的桌面（KDE/GNOME 扩展均可）。
- **游戏界面撕裂 / 掉帧**：在「方案 → 增强」里开 MangoHud 看是 GPU 还是 CPU 瓶颈，需要合成器的话开 gamescope。
